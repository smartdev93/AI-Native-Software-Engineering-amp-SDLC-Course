# Fix six claims, then pin every tool

Most of the draft syllabus holds up as of October 8, 2026, but six claims need fixing before release. Two are simply wrong: `intent.md` is not a Spec Kit, OpenSpec or Kiro artifact, and BMAD no longer ships a QA persona. One is overstated: the "23 syllabi" study exists, but it reports observed medians from 14 courses and recommends no weights. Two are right but out of date in their notation: `/checklist` and `/converge` are both real core Spec Kit commands, but the current docs write them `/speckit.checklist` and `/speckit.converge`. One needs to be demoted: Shiplight AI is a real but early-stage vendor, so it belongs in an optional case study, not on the core reading list. The bigger risk is that the tools change faster than a semester. Spec Kit shipped v1.0.0 to v1.1.2 between August 21 and October 7, 2026. MCP's July 28, 2026 revision removed the handshake and sessions. BMAD's agent roster changed. Lectures built on 2025 tutorials will teach commands and protocol details that no longer exist. Pin every tool version in the labs, cite primary docs rather than blogs, and present the vendor-funded productivity and code-quality numbers as directional evidence. Every claim below links to the source the research notes verified. Where the notes flagged a gap, the report says so instead of filling it.

## Four draft claims are wrong or overstated, and two need new wording

**The 23-syllabi source is real, and the claim needs to shrink to fit it.** Francis Geng, Leo Porter and colleagues analyzed **23 publicly available syllabi** of US upper-division, credit-bearing courses that require GenAI use in graded SE work ([arXiv](https://arxiv.org/abs/2608.05898)). The paper was submitted August 6, 2026 and is a preprint. The assessment weights come from only **14 percentage-graded courses**. Project or capstone work had a median of **50% (range 30–85%)**, participation a median of 17.5%, and review/reflection a median of 19%. Proctored assessment appeared in only **3 courses**, with a median of 20% ([arXiv HTML](https://arxiv.org/html/2608.05898)). The authors prescribe no weights. They say course materials "cannot show … how effective the courses were for learning" ([arXiv HTML](https://arxiv.org/html/2608.05898)). The draft's 50–60% capstone sits inside the observed range. Its oral-defense weight of 10–15% is lower than CMU 15-113, which puts **20% on oral evaluations plus quizzes** and holds a TA "mock job interview" after each project ([CMU 15-113](https://www.cs.cmu.edu/~113/)). There is a smaller fix too: the draft's ranges add up to anywhere from 90% to 120%. Fixed weights should add to 100%. A version consistent with the evidence would be 40–50% project, 15–25% individually verified work (oral or proctored), plus process logs. That proposal is a synthesis, not a finding from any one study, because no controlled study compares weightings.

**Spec Kit's `/checklist` and `/converge` are real, and `/converge` is new.** Spec Kit's reference page lists ten agent commands. Seven are core (constitution, specify, plan, tasks, implement, converge, taskstoissues) and three are optional quality gates (clarify, analyze, checklist). The canonical order is `/speckit.constitution → specify → clarify → plan → checklist → tasks → analyze → implement → converge` ([Agentic SDD reference](https://github.github.io/spec-kit/reference/agentic-sdd.html)). `/speckit.converge` arrived in **v0.11.2 on June 18, 2026**. As of v1.1.0, `taskstoissues` is deprecated in favor of a bundled `github` extension ([CHANGELOG](https://github.com/github/spec-kit/blob/main/CHANGELOG.md)). Any reading written before mid-2026, including the September 2, 2025 launch post, does not mention converge ([GitHub Blog](https://github.blog/ai-and-ml/generative-ai/spec-driven-development-with-ai-get-started-with-a-new-open-source-toolkit/)). That post is fine to assign as history, with that caveat.

**`intent.md` belongs to IntentSpec, not to any mainstream SDD tool.** IntentSpec is an MIT-licensed format stewarded by **Pathmode** whose canonical file is `intent.md`, with sections for objective, outcomes, constraints, edge cases and verification. An adapter feeds it into OpenSpec ([pathmodeio/intentspec](https://github.com/pathmodeio/intentspec)). Spec Kit's methodology document talks about "intent-driven development" but defines no such file ([spec-driven.md](https://github.com/github/spec-kit/blob/main/spec-driven.md)). The research did not establish how widely IntentSpec is used.

## Module 1 must teach the July 2026 MCP revision, not the 2025 one

**The agent architecture is the same across vendors.** Claude Code describes a loop of "gather context, take action, and verify results." The model reasons, and an "agentic harness" supplies the tools and manages context ([How Claude Code works](https://code.claude.com/docs/en/how-claude-code-works)). GitHub now calls its product **Copilot cloud agent**. It plans, edits, runs tests in an ephemeral cloud environment and opens a PR ([GitHub Docs](https://docs.github.com/en/copilot/concepts/agents/coding-agent/about-coding-agent)). Gemini CLI is Apache-2.0 and supports MCP through `~/.gemini/settings.json` ([gemini-cli](https://github.com/google-gemini/gemini-cli)). One model of the architecture covers all of them: model, tools, context manager, permission/sandbox layer, and human interrupts. The tools differ mainly in where code runs and whether the output is local edits or a PR. The notes did not fetch Cursor's or Codex's own loop descriptions, so check those before writing that slide.

**Context files are soft context, not enforced configuration.** Claude Code loads `CLAUDE.md` from the working directory and every directory above it and concatenates them. Files closer to the launch directory are read last. The docs recommend keeping each file **under 200 lines**, and they state plainly that Claude "treats them as context, not enforced configuration". To block an action reliably, use a PreToolUse hook ([Claude Code memory](https://code.claude.com/docs/en/memory)). Claude Code reads `AGENTS.md` natively only from **v2.1.277**. On older versions, put an `@AGENTS.md` import in CLAUDE.md ([Claude Code memory](https://code.claude.com/docs/en/memory)). AGENTS.md is now stewarded by the **Agentic AI Foundation under the Linux Foundation** ([agents.md](https://agents.md/)), which was announced on December 9, 2025 with MCP, goose and AGENTS.md as founding projects ([Linux Foundation](https://www.linuxfoundation.org/press/linux-foundation-announces-the-formation-of-the-agentic-ai-foundation)). Codex caps the combined AGENTS.md content at 32 KiB by default ([Codex docs](https://learn.chatgpt.com/docs/agent-configuration/agents-md)). Gemini CLI reads AGENTS.md only if it is added to `context.fileName` ([GEMINI.md docs](https://github.com/google-gemini/gemini-cli/blob/main/docs/cli/gemini-md.md)). Copilot reads AGENTS.md, CLAUDE.md and GEMINI.md ([GitHub Docs](https://docs.github.com/en/copilot/reference/custom-instructions-support)). The portable lab pattern is a canonical AGENTS.md, a one-line CLAUDE.md that imports it, and a Gemini `context.fileName` setting. That pattern is a synthesis of the docs; no single vendor prescribes it.

**The context-rot lecture has strong citations.** Liu et al. (TACL) show that performance is highest when the relevant information sits at the start or end of the input and drops in the middle ([arXiv:2307.03172](https://arxiv.org/abs/2307.03172)). Chroma tested **18 models** and found that "LLMs do not maintain consistent performance across input lengths" even on trivial tasks ([Chroma Research](https://www.trychroma.com/research/context-rot)). Chroma's report is an industry technical report and has not been peer reviewed. Anthropic describes context as a finite "attention budget." Its mitigations are compaction, structured notes, sub-agents that return summaries of roughly 1,000–2,000 tokens, and just-in-time retrieval ([Anthropic Engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)).

**MCP changed substantially in 2026.** The current spec revision is **2026-07-28**. It removes the `initialize` handshake and `Mcp-Session-Id` sessions, so the protocol is now stateless and each request carries its version and capabilities in `_meta`. It adds `server/discover`, moves Tasks to an extension, and deprecates Roots, Sampling and Logging. It also sets a minimum 12-month deprecation window ([MCP changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog)). The core primitives are still Tools, Resources and Prompts over JSON-RPC 2.0, with two transports: stdio and Streamable HTTP ([MCP spec](https://modelcontextprotocol.io/specification/latest); [Transports](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports)). On security, the spec says tool annotations are untrusted unless they come from a trusted server, and that "MCP itself cannot enforce these security principles at the protocol level" ([MCP spec](https://modelcontextprotocol.io/specification/latest)). The notes did not confirm whether the Python and TypeScript SDKs implement 2026-07-28 yet. Tell students which revision their SDK targets.

**The lab commands come straight from the docs.** Install Claude Code with `curl -fsSL https://claude.ai/install.sh | bash` (or brew, winget or npm with Node 22+), then check it with `claude --version` and `claude doctor` ([Setup](https://code.claude.com/docs/en/setup)). Run `/init`, then inspect context with `/context` and `/compact <focus>` ([Memory docs](https://code.claude.com/docs/en/memory)). Add MCP servers with `claude mcp add --transport http notion https://mcp.notion.com/mcp`, using `--scope project` to write a committed `.mcp.json`, and verify with `/mcp` ([Claude Code MCP](https://code.claude.com/docs/en/mcp)). For the server-building exercise, follow the official weather quickstart (`uv add "mcp[cli]"`, `@mcp.tool()`). Its main pitfall: never write to stdout from a stdio server ([Build an MCP server](https://modelcontextprotocol.io/docs/develop/build-server)). Budget is a real constraint. Claude Code requires a Pro, Max, Team, Enterprise or Console account ([Setup](https://code.claude.com/docs/en/setup)). Gemini CLI's Google sign-in gives **60 requests/min and 1,000/day free** ([gemini-cli](https://github.com/google-gemini/gemini-cli)), so every lab needs a Gemini path. The notes did not verify Gemini's `mcp add` syntax, its minimum Node version, or Cursor's free tier.

**The SDLC-shift lecture should present the data as contested.** DORA 2025 reports **90% AI adoption**. AI use now correlates with higher throughput but still with lower delivery stability, and the report sums up: "AI doesn't fix a team; it amplifies what's already there" ([Google Cloud](https://cloud.google.com/blog/products/ai-machine-learning/announcing-the-2025-dora-report)). METR's July 2025 RCT found experienced developers **19% slower**, although they believed they were 20% faster ([METR](https://metr.org/blog/2025-07-10-early-2025-ai-experienced-os-dev-study/)). METR's February 2026 update estimates −18% and −4% changes in completion time, both with confidence intervals that cross zero, and METR itself calls that data unreliable ([METR 2026](https://metr.org/blog/2026-02-24-uplift-update/)). Secondary sources disagree on whether "−18%" means faster or slower, so quote METR verbatim. Stack Overflow 2025 found that 84% use or plan to use AI but only **33% trust its accuracy** ([Stack Overflow](https://survey.stackoverflow.co/2025/ai)). The notes did not check whether 2026 DORA or Stack Overflow data has been published.

## Module 2 labs should pin Spec Kit v1.1.2 and contrast it with OpenSpec deltas

**Spec Kit setup changed in 2026.** The latest release is **v1.1.2 (October 7, 2026)** ([CHANGELOG](https://github.com/github/spec-kit/blob/main/CHANGELOG.md)). It requires Python 3.11+ and uv. Install it with `uv tool install specify-cli`, pin it with `--from git+https://github.com/github/spec-kit.git@v1.1.2`, and check it with `specify version` ([Installation](https://github.github.io/spec-kit/installation.html)). Projects start with `specify init <name> --integration claude|copilot|gemini`. Non-interactive runs default to Copilot, and `--here --force` is the way to use an existing repository ([Installation](https://github.github.io/spec-kit/installation.html); [Existing projects](https://github.github.io/spec-kit/guides/existing-projects.html)). Git is now optional and provided by an extension (`specify extension add git`), and the active feature is tracked in `.specify/feature.json` ([Quickstart](https://github.github.io/spec-kit/quickstart.html)). The README warns that the commands "are agent skills, not terminal commands" ([README](https://github.com/github/spec-kit)). The lab handout should separate terminal steps from agent-chat steps.

**The convergence loop is a built-in feature, not something the course has to invent.** `/speckit.converge` "assesses the codebase against the feature's spec, plan, and tasks." It is append-only, and its only possible write is new tasks under a Convergence section in tasks.md. Students repeat implement → converge until it reports **Converged** ([Agentic SDD reference](https://github.github.io/spec-kit/reference/agentic-sdd.html)). `/speckit.checklist` produces "unit tests for your requirements" that reviewers own. `/speckit.implement` asks before proceeding if any item is unchecked. `/speckit.clarify` asks up to five questions, and `/speckit.analyze` is a read-only consistency check ([Agentic SDD reference](https://github.github.io/spec-kit/reference/agentic-sdd.html)). The verified lab sequence is: constitution, specify, clarify, plan, checklist (a human ticks the items), tasks, analyze (fix problems at the source), implement, then converge repeatedly. A change-request round under the living-spec model follows, in which students edit spec.md and rerun from plan ([Evolving specs](https://github.github.io/spec-kit/guides/evolving-specs.html)). The rule that students may only refine specs is a course constraint. Grade it from git diffs, the number of converge passes, the analyze reports and the reviewed checklists. Agent output varies between runs, so the pass count cannot be predicted.

**OpenSpec covers the brownfield half.** It keeps current truth in `openspec/specs/` and proposals in `openspec/changes/<name>/`. Archiving a change merges its ADDED, MODIFIED and REMOVED delta requirements into the main specs ([concepts.md](https://github.com/Fission-AI/OpenSpec/blob/main/docs/concepts.md)). The current version is **1.14.1** (October 5, 2026), and it requires Node 20.19.0+ ([npm](https://registry.npmjs.org/@fission-ai/openspec); [README](https://github.com/Fission-AI/OpenSpec)). Commands now use the **OPSX** form: `/opsx:propose`, `/opsx:apply` and `/opsx:archive` replace the legacy `/openspec:proposal|apply|archive` ([migration guide](https://github.com/Fission-AI/OpenSpec/blob/main/docs/migration-guide.md)). `openspec validate <change> --strict` works as a CI gate ([CHANGELOG](https://github.com/Fission-AI/OpenSpec/blob/main/CHANGELOG.md)). Spec Kit's brownfield answer is different. It is a choice among flow-forward, living-spec and flow-back persistence models, plus a warning against retroactively specifying every existing behavior ([Existing projects](https://github.github.io/spec-kit/guides/existing-projects.html)). That contrast is the core of the brownfield lecture.

**EARS needs its primary citation.** Alistair Mavin and colleagues at Rolls-Royce created EARS while analyzing jet-engine airworthiness regulations ([alistairmavin.com](https://alistairmavin.com/ears/)). It was published at RE'09 in Atlanta, pp. 317–322 ([IEEE Xplore](https://ieeexplore.ieee.org/document/5328509)); confirm the document number before citing it. It has five patterns: ubiquitous, state-driven (While), event-driven (When), optional feature (Where) and unwanted behaviour (If/Then), plus combinations ([alistairmavin.com](https://alistairmavin.com/ears/)). Kiro writes EARS directly into `requirements.md`, alongside `design.md` and `tasks.md` ([Kiro Specs](https://kiro.dev/docs/specs/)). OpenSpec scenarios use GIVEN/WHEN/THEN instead ([concepts.md](https://github.com/Fission-AI/OpenSpec/blob/main/docs/concepts.md)). Teach EARS as the way to write the requirement sentence and the scenarios as the test layer.

**The critique readings are needed for balance.** Birgitta Böckeler's October 15, 2025 piece sets out the spec-first, spec-anchored and spec-as-source levels. It reports a small Kiro bug fix that produced 4 user stories and 16 acceptance criteria, and it warns of model-driven development's mix of "inflexibility *and* non-determinism" ([martinfowler.com](https://martinfowler.com/articles/exploring-gen-ai/sdd-3-tools.html)). Thoughtworks put SDD in **Assess** on November 5, 2025, warning that "handcrafting detailed rules for AI ultimately doesn't scale" ([Thoughtworks Radar](https://www.thoughtworks.com/radar/techniques/spec-driven-development)). The Radar volume number is disputed (33 vs 34), so check it. Böckeler wrote before converge and the brownfield guides existed, so her point about workflow size is partly addressed now. Her points about review overhead and agents ignoring specs still stand.

## Module 3 should parallelize reading, centralize writing and gate with deterministic tools

**BMAD's roster changed, so teach it from the repo.** The npm package `bmad-method` is at **6.12.1** (October 4, 2026) ([npm](https://registry.npmjs.org/bmad-method)). The current reference page says the module "installs five named agents": Analyst (Mary), PM (John), Architect (Winston), Developer (Amelia) and UX Designer (Sally). It also says "the Technical Writer (Paige) is on hiatus" and that QA test generation now runs from the Developer's menu, with the full Test Architect as a separate module ([skills-and-agents.md](https://github.com/bmad-code-org/BMAD-METHOD/blob/main/docs/reference/skills-and-agents.md)). Third-party guides still list Scrum Master (Bob) and QA (Quinn) and give `npx bmad-method install` as the install command ([Augment Code](https://www.augmentcode.com/guides/bmad-method-ai-development)). The current README instead uses `npx skills add bmad-code-org/BMAD-METHOD` or plugin marketplaces ([repo](https://github.com/bmad-code-org/BMAD-METHOD)).

**Assign the two multi-agent essays as a pair.** Anthropic reports that an Opus 4 orchestrator with Sonnet 4 workers beat single-agent Opus 4 by **90.2%** on an internal research eval. Multi-agent runs used about **15x the tokens** of chat ([Anthropic](https://www.anthropic.com/engineering/multi-agent-research-system)). Cognition's "Don't Build Multi-Agents" argues that parallel agents make conflicting implicit decisions on tasks that need shared context ([Cognition](https://cognition.com/blog/dont-build-multi-agents)). The two fit together. Research tasks mostly read and parallelize well, while coding tasks write and do not, which gives the heuristic "parallelize reading, centralize writing." Claude Code subagents put this into practice. They are Markdown files with YAML frontmatter in `.claude/agents/`, each starts with a fresh isolated context, the built-in Explore and Plan agents are read-only, and nesting defaults to a depth of 3 ([Claude Code subagents](https://code.claude.com/docs/en/sub-agents)).

**Verification and validation should rest on Playwright, with Shiplight as an optional extra.** Playwright 1.56 added **planner, generator and healer** test agents, installed with `npx playwright init-agents --loop=claude|vscode|opencode|codex`. The planner writes Markdown plans in `specs/`, which map directly to acceptance criteria ([Playwright test agents](https://playwright.dev/docs/test-agents)). The current `@playwright/test` version is 1.64.0 ([npm](https://registry.npmjs.org/@playwright/test/latest)). One warning for the lecture: a healer that patches failing tests can hide regressions, so its diffs need human review. Playwright MCP drives a browser through the accessibility tree, but its README now recommends the CLI plus Skills for coding agents as "more token-efficient" ([playwright-mcp](https://github.com/microsoft/playwright-mcp)). Shiplight AI saves verified flows as YAML (`goal`, `statements`, `intent:`, `VERIFY:`) and can transpile them to plain Playwright files ([Shiplight docs](https://docs.shiplight.ai/local/yaml-tests)). However, its npm package is at **0.1.106**, its skills repo is **archived with 2 stars** ([GitHub API](https://api.github.com/repos/shiplightai/agent-skills)), and its "10x faster" and customer claims come from the CEO's own blog ([Shiplight blog](https://www.shiplight.ai/blog/what-is-shiplight)). Maestro (Apache-2.0, about 16k stars) is the established open-source example of YAML-flow E2E testing ([Maestro](https://docs.maestro.dev/)). For load testing, k6 **v2.3.0** (September 21, 2026) is current ([releases](https://github.com/grafana/k6/releases)). `k6 x agent` installs skill bundles and registers an MCP server that k6 describes as experimental ([Grafana docs](https://grafana.com/docs/k6/latest/set-up/configure-ai-assistant/bootstrap-with-k6-x-agent/)).

**Static analysis gates now integrate with agents.** Ruff is current at 0.16.10 ([PyPI](https://pypi.org/project/ruff/)). Semgrep's MCP server has moved into the main `semgrep` binary as a beta ([semgrep/mcp](https://github.com/semgrep/mcp)); the exact command was not verified. SonarQube Server 2026.5 offers AI Code Assurance, including a "Sonar way for agentic AI" quality gate ([Sonar docs](https://docs.sonarsource.com/sonarqube-server/quality-standards-administration/ai-code-assurance/overview)). The draft's claim about blocking secrets needs two more tools: gitleaks v8.30.1 ([GitHub](https://github.com/gitleaks/gitleaks)) and GitHub push protection, which now also covers "GitHub MCP interactions" ([GitHub Docs](https://docs.github.com/en/code-security/secret-scanning/introduction/about-push-protection)). Teach the layers in order: agent-side Ruff and Semgrep, pre-commit gitleaks, server-side push protection, and a CI quality gate. The notes did not check SonarQube licensing.

**Evals in CI.** promptfoo publishes an official GitHub Action that uses an `on.pull_request.paths` filter ([promptfoo docs](https://www.promptfoo.dev/docs/integrations/github-action/)). OpenAI announced on **March 9, 2026** that it would acquire Promptfoo, and the founders say it will stay open source ([OpenAI](https://openai.com/blog/openai-to-acquire-promptfoo)). Inspect from UK AISI ([docs](https://inspect.aisi.org.uk/)) and DeepEval ([GitHub](https://github.com/confident-ai/deepeval)) are the open-source alternatives. Anthropic's "Demystifying evals for AI agents" (January 9, 2026) supplies the vocabulary: tasks, trials, graders, capability vs regression evals, **pass@k vs pass^k**, and "grade outcomes, not paths" ([Anthropic](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)). In the lab, the eval suite runs whenever `CLAUDE.md`, `AGENTS.md`, `.claude/agents/**` or `prompts/**` changes. The workflow file in the notes was written for the course, and its `promptfoo eval -c` flags still need checking against the docs.

**The code-quality evidence comes from vendors.** Veracode found security flaws in **45%** of AI code tasks and saw no improvement with larger models ([Veracode](https://www.veracode.com/press-release/ai-generated-code-poses-major-security-risks-in-nearly-half-of-all-development-tasks-veracode-research-reveals/)). CodeRabbit found about **1.7x more issues** in AI-co-authored PRs ([CodeRabbit](https://www.coderabbit.ai/blog/state-of-ai-vs-human-code-generation-report)). GitClear reports an **8x rise** in duplicated blocks during 2024; the notes cite it only through secondary coverage ([DevClass](https://devclass.com/2025/02/20/ai-is-eroding-code-quality-states-new-in-depth-report/)). Each vendor sells a fix for the problem it measured, and that conflict of interest is itself worth discussing in class.

## Module 4 must separate a provocative preprint from team-level evidence

**"Cognitive debt" has two meanings, and the course needs to keep them apart.** The MIT Media Lab preprint by Kosmyna et al. studied **essay writing, not coding**, with 54 participants, of whom only 18 completed the crossover session. It found that LLM users "consistently underperformed at neural, linguistic, and behavioral levels" ([arXiv:2506.08872](https://arxiv.org/abs/2506.08872)). It is still not peer reviewed. Margaret-Anne Storey's February 9, 2026 essay carries the term into software as the erosion of a team's shared theory of the system, building on Naur. Her mitigations are that one human must understand every AI change, that changes document *why*, and that teams hold regular checkpoints ([Storey](https://margaretstorey.com/blog/2026/02/09/cognitive-debt/)). The strongest evidence is Anthropic's January 2026 RCT. In it, 52 mostly junior engineers learned the Trio library, and those with AI help scored **50% vs 67%** on a comprehension quiz (d = 0.738, p = 0.01) with no significant speed gain. Learners who asked AI for explanations or conceptual answers scored higher than those who delegated the work ([Anthropic](https://www.anthropic.com/research/AI-assistance-coding-skills); [arXiv:2601.20245](https://arxiv.org/abs/2601.20245)). Lee et al. (CHI 2025, 319 knowledge workers) found that higher confidence in GenAI went with less critical thinking, though this is self-reported ([PDF](https://advait.org/files/lee_2025_ai_critical_thinking_survey.pdf)). No longitudinal study of skill loss among professional developers turned up.

**AI code review helps, but it should not be the gate.** Copilot code review became generally available on April 4, 2025 ([GitHub changelog](https://github.blog/changelog/2025-04-04-copilot-code-review-now-generally-available/)). The claim that it only comments, and never approves, comes from a third-party guide and needs confirming in GitHub's docs. An industrial study of 4,335 PRs found that **73.8%** of AI comments were resolved, but average PR close time rose from **5h52m to 8h20m** ([arXiv 2412.18531](https://arxiv.org/abs/2412.18531v2)). Across 22,000+ comments from 16 tools, AI review comments that were concise, included code, and were tied to a specific code hunk were more likely to lead to changes ([arXiv 2508.18771](https://arxiv.org/abs/2508.18771v1)). For the capstone, make AI review a required but non-blocking check, with a human CODEOWNER giving final approval.

**The security lecture can build on documented incidents.** Prompt injection is LLM01 in OWASP's 2025 LLM Top 10. A separate **Agentic Top 10 (ASI01–ASI10)** came out on December 9, 2025 ([OWASP GenAI](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026)); the notes did not fetch its item names. Willison's "lethal trifecta" (private data, untrusted content, external communication) is the framework to teach first ([Willison](https://simonwillison.net/2025/jun/16/the-lethal-trifecta/)). Three cases follow from it. First, the GitHub MCP "toxic agent flow," where a public issue led an agent to leak private repository data ([Invariant Labs](https://invariantlabs.ai/blog/mcp-github-vulnerability)). Second, the Nx "s1ngularity" attack, the first known supply-chain attack to use installed AI CLIs for reconnaissance ([Wiz](https://www.wiz.io/blog/s1ngularity-supply-chain-attack)). Third, the Amazon Q extension wiper prompt, which the notes cite from secondary press only ([CyberInsider](https://cyberinsider.com/amazons-ai-coding-assistant-for-vsc-infected-with-data-wiper/)). Shai-Hulud is a classic npm worm, not an AI attack ([CISA](https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem)). For package hallucination, Spracklen et al. (USENIX Security 2025) found hallucination rates of at least 5.2% for commercial models and **21.7%** for open-source models across 576,000 samples ([arXiv:2406.10279](https://arxiv.org/abs/2406.10279)). Do not use the "19.7% overall" figure that circulates; the notes did not find it in the paper.

**Governance and ADRs.** NIST SP 800-218A (July 26, 2024) adds GenAI practices to SSDF ([NIST](https://csrc.nist.gov/pubs/sp/800/218/a/final)). Under the EU AI Omnibus, Annex III high-risk obligations now start **December 2, 2027** ([FPF](https://fpf.org/?p=250371)). The sources disagree on the Omnibus entry-into-force date (July 24 vs July 27, 2026), so check the Official Journal. The US Copyright Office holds that purely AI-generated material is not copyrightable ([copyright.gov](https://copyright.gov/newsnet/2025/1060.html)). The Linux kernel requires an `Assisted-by:` tag and forbids AI from adding Signed-off-by ([FOSSID](https://fossid.com/articles/linux-kernel-ai-coding-policy-enterprise-accountability/)); in 2026 developers were again debating whether to keep the tag ([Phoronix](https://phoronix.com/news/Linux-AI-Attribution-Again)). For ADRs, cite Nygard's November 15, 2011 post, with its Title, Context, Decision, Status and Consequences sections ([Cognitect](https://cognitect.com/blog/2011/11/15/documenting-architecture-decisions)), and MADR as the template ([ozimmer.ch](https://ozimmer.ch/practices/2022/11/22/MADRTemplatePrimer.html)). Before release, still to do: fetch ISO/IEC 42001, the current MADR version, and the primary policy pages for the kernel, Gentoo, NetBSD and QEMU.

## Conclusion

The draft's structure is sound. Its weak points are version drift and sources stated more strongly than they support. A course built in October 2026 is teaching a field where Spec Kit added its signature loop four months ago, the MCP handshake went away in July, and BMAD's roster changed within a single major version. The rule that follows is to grade the practices and not the command names. Pin each tool to a tagged release in a `TOOLS.md` lab manifest (Spec Kit v1.1.2, OpenSpec 1.14.1, BMAD 6.12.x, MCP 2026-07-28, Playwright 1.64), and re-verify the manifest the week before each module.

The evidence also points toward the course's own premise. Experienced developers misjudged their AI speedup by about 40 percentage points (believed 20% faster, measured 19% slower). Juniors who delegated to AI learned less. AI review slowed PR closure. All three findings argue for weighting graded work toward individually verified understanding, meaning oral defense, process logs and ADRs written and owned by a human, rather than toward the volume of the team artifact. Shifting 5–10 points from the capstone to the oral and proctored component would bring the course in line with the one verified course (CMU) that already does this. It would also make the cognitive-debt module something students practice, not just a lecture topic.
